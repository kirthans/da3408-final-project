# Guess the Elo

**DA3408 AIOps Lab, course project.** Give the app one chess game (PGN). It estimates both players' **Lichess-equivalent ratings** with an **80% interval**, and shows the **moves that most influenced the estimate**. The ratings written in the file are never used.

Behind the app:
- an offline pipeline under **DVC**: **Spark** ingests the Lichess database and **Ray** runs Stockfish analysis;
- an **XGBoost** model with conformal intervals, tracked in **MLflow** and served by the MLflow scoring server behind **FastAPI**;
- **Prometheus**, **Alertmanager** and **Grafana** watch the model on a month-by-month replay of 2020, retrain it automatically when its error drifts, and promote the new model only if it is better.

## Run it

**Requirements:**
- Linux with Docker Engine and Compose v2;
- conda (or mamba);
- about 16 GB RAM;
- Java 17 for Spark, needed only for the offline pipeline.

```bash
conda env create -f environment.yml && conda activate da3408-project
make setup                      # pip install -e ".[dev]"
cp .env.example .env            # set API_KEY and GRAFANA_ADMIN_PASSWORD
make test lint                  # unit + contract tests, ruff + black
```

**1. Build the data and the model (offline pipeline).**

```bash
make stockfish                  # fetch the Stockfish binary into tools/
dvc repro                       # download → Spark ingest/sample → Ray+Stockfish analysis → train → evaluate → register
```

The full sample (16 months, 200,000 analysed games) takes about 5 hours of Stockfish time on a 12-thread laptop.

- **Faster check:** lower `data.max_games_per_month` and the `sample.*` sizes in `params.yaml`.
- **Data storage:** DVC data lives on an SSH remote on the author's machine, which a fresh clone cannot reach, so `dvc repro` rebuilds the data from the public Lichess dumps.
- **To use your own remote:**

  ```bash
  dvc remote modify --local storage url ssh://<host>/<path>
  ```

  Add `user` and `keyfile` the same way.

**2. Start the services.**

```bash
make trainer-config             # writes the trainer's DVC settings from .dvc/config.local
make up                         # builds and starts the 10 Compose services
```

| Service | URL | Notes |
|---|---|---|
| Web app (frontend) | http://localhost:8080 (https://localhost:8443 after `make certs`) | Estimate and Pipeline tabs. Demo data without a backend: `/?mock=1` |
| API (FastAPI) | http://localhost:8000/docs | Talks to the model server; all routes in `docs/lld.md` |
| MLflow | http://localhost:5000 | Experiments, runs, model registry |
| Model server | http://localhost:5001 | `mlflow models serve` on `models:/elo-estimator@champion` |
| Grafana | http://localhost:3000 | "Service health" and "Model quality, drift and pipeline" dashboards |
| Prometheus / Alertmanager | http://localhost:9090, http://localhost:9093 | Alert rules in `infra/prometheus/rules.yml` |
| Trainer / monitor | http://localhost:8001, http://localhost:8002 | Retrain controller; replay clock |

Every port except the frontend is bound to 127.0.0.1.

**3. Run the drift demo.**

```bash
make replay-reset               # baseline model, replay clock at zero
make replay-play                # reveal one 2020 month per interval (REPLAY_INTERVAL_S in .env shortens it)
make replay-status
```

When the error stays above 1.04 × the reference for 2 minutes, `ModelMAEDegraded` fires. Alertmanager then calls the trainer, which runs `dvc repro register`, applies the gate and moves the `@champion` alias. You can watch this in the Pipeline tab and in Grafana.

- `make rollback` restores the previous champion.
- `make sync` pushes the new data and model to the DVC remote.

## Repository layout

```
src/elo/            shared Python package
  pgn/ engine/ features/      PGN parsing and leakage stripping, Stockfish wrapper, per-move features
  data/                       download, Spark ingest and sampling, Ray analysis
  models/ training/           aggregation, conformal, pyfunc, sweep, registry, retrain controller
  monitoring/ api/ common/    drift monitor, FastAPI app, config, logging, errors
services/           one Dockerfile per service: api, frontend (nginx + static site), model_server, mlflow, monitor, trainer
infra/              Prometheus rules, Alertmanager, Grafana provisioning and dashboards
tests/              unit, contract (AC4), integration (smoke), load (AC3), fixtures (Git LFS)
dvc.yaml dvc.lock params.yaml    pipeline DAG, pinned hashes, all parameters
MLproject python_env.yaml        MLflow project entry points and environment
reports/            metrics, validation counts, throughput, test results, AC5 evidence (written by the pipeline)
docs/               report and the mandatory documents; img/ holds screenshots (Git LFS)
```

**Versioning:**
- **Git** holds code and configuration.
- **Git LFS** holds test PGNs and screenshots.
- **DVC** holds data and models.
- **MLflow** holds runs and model versions; every run records its git commit and the DVC data hash.
